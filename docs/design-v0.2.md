**《地城拾遗》游戏策划评审稿 v0.2**

日期：2026-09-23。暂定名，仅用于讨论。状态：已根据用户评审更新核心规则，进入原型规格准备。

本文把用户提出的刷宝、随机词条、经典 RPG 属性、塔科夫式背包与仓库、经济养成、TRPG 地下城探索整合成一套方案。所有数值、内容数量、周期和测试门槛均为待验证的设计提案，不是已实现功能或行业统计。

**1. 产品定位与默认前提**

一句话定位：一款以“带什么下地城、怎样走位并选择行动、什么值得带回来”为核心决策的单人战术刷宝 RPG。

玩家扮演地下遗迹边缘城镇中的拾遗者。进入废弃矿坑与封印遗址，回收古代装备；通过战斗、工具和属性处理事件；判断战利品的价值，在背包和生存资源耗尽前撤离。回城后鉴定、出售、拆解、打造、整理收藏，准备下一次探索。

默认提案：单角色、单机优先、2D、鼠标键盘、中文界面、每局 15–25 分钟、装备驱动流派、离线可运行。网页作为试玩入口，Windows 下载版作为长期游玩载体。用户已接受其余整体方向；本轮确定以行动后掷骰结算替换骰子分配，并采用有特色的二次元美术。具体数值、预算和商业化目标仍待验证。

设计支柱：

- 刷到的东西能改变下一次出发的选择，不只是把数字换大。
- 运气提供局面，装备和玩家决策提供处理局面的办法。
- 背包空间使撤离与携带产生取舍，仓库功能让长期收藏保持轻松。
- 经济是组织装备成长的工具，不能让最优策略变成反复倒卖或无脑抽奖。

**2. 核心循环与三层目标**

单次循环：选择目标与路线 → 配装、带补给 → 地城探索 → 事件与战斗 → 搜刮、估值、重新装包 → 继续深入或撤离 → 鉴定与结算 → 出售／拆解／收藏／装备 → 打造与升级 → 再次出发。

| 时间尺度 | 玩家目标 | 对应奖励 |
| --- | --- | --- |
| 每个回合或房间 | 用行动、移动力、道具和生命换取更好结果 | 减少损失、取得额外宝物、揭示路线 |
| 每次探索 | 带回至少一件值得保留的物品或有效进度 | 可用装备、目标材料、金币、委托进度 |
| 多次探索 | 完善流派、找到好底材、征服更深区域 | 稀有组合、制作解锁、仓库升级、首领收藏 |

反复游玩的动力分三类：确定性目标材料、可定向刷取的装备家族、低概率极品。不能只保留第三类。

**3. 探索结构与撤离**

推荐房间节点地图，战斗进入小型俯视／斜俯视方格场地，加入移动力、障碍和视线。完整自由行走地图不是第一阶段必要条件。先用地图分支表达探索，再用角色移动、开箱、采集和交互动画表达空间感。

每局约 8–12 个经过的节点，分 2–3 段；地图总节点可更多，由分支产生选择。每段安排一个营地或明确出口，首领是高回报目标，并非所有探索的强制终点。每进入一个新房间提升地城警戒，不按现实时间惩罚整理背包。

| 节点 | 玩法 | 主要取舍 |
| --- | --- | --- |
| 普通战斗 | 读取敌人预告，安排站位与技能 | 保存生命还是快速解决 |
| 精英战斗 | 敌人拥有可辨认机制，掉落池更集中 | 是否为目标词条承受额外风险 |
| 遗物矿脉 | 选择挖掘方式、使用镐具、进行检定 | 消耗工具换取底材，或浅采后离开 |
| 陷阱／密室 | 力量破拆、敏捷解除、感知寻找绕路 | 属性路线与道具路线的成本不同 |
| 神龛 | 接受带代价的临时增益 | 当前安全与后续收益交换 |
| 商人／营地 | 补给、恢复、少量鉴定或撤离 | 花钱保住战利品，还是保留资金 |
| 宝库 | 宝物多，但可能提高警戒或触发守卫 | 容量与撤离风险同时上升 |

事件至少有两种可理解的解决路线。例：封印门可以力量破坏、消耗符文钥匙直接打开、用感知找小路，或放弃。检定前显示成功条件、概率、消耗，以及已知失败代价；未知后果明确标为未知。失败应推进局面，例如受伤但得到部分物品、触发战斗、失去工具，而非无事发生后允许无限重试。

撤离规则：出口节点确定性撤离；营地可购买或补充逃脱道具；非战斗中消耗逃脱道具可提前撤离；战斗中逃脱作为需要投入行动的技能，并显示风险。不要在成功撤离动画最后追加不可预测的全损骰。

**4. 战斗与“操作感”：战术走位＋行动后掷骰**

已确认方向：参考用户提出的 COC／TRPG 检定思路，骰子用于决定是否命中、造成多少伤害和事件结果。玩家先选择行动和位置，再掷骰结算。取消“先掷两个骰子再分配到技能槽”的方案。以下为适配刷宝游戏的自定义规则，不是照搬 COC 原规则。

命中与事件采用 d100 百分骰（1–100），伤害采用武器／技能定义的伤害骰，例如 1d6、2d6。界面先显示概率和伤害区间，确认后生成结果，再播放简洁的骰子与角色动画。

建议战场原型为 8×6 方格，每场 1–3 个敌人。四方向移动，每格消耗 1 点移动力；不允许穿墙或穿过敌人，不采用会造成额外歧义的斜向距离。障碍影响路线与远程视线。技能必须同时满足射程、视线和目标条件，才可确认。

每轮每个单位获得一个回合，按速度从高到低行动；速度相同时使用稳定的平局顺序，不每次随机跳动。每回合 2 点行动点（AP），基础移动力提案为 4；移动池可分段使用，攻击前后均可移动。普通攻击消耗 2 AP；部分辅助技能或道具消耗 1 AP；冲刺花 1 AP 换取额外移动，每回合限一次。技能位移另受 AP、冷却及落点合法性约束。所有数值需试玩调节。

速度只决定每轮行动顺序，第一版不提高每轮行动次数。移动力决定走多少格；敏捷影响命中／回避及对应事件检定。避免三者同时提高攻击频率而形成唯一最优属性。

命中原型：
`有效命中率 H = clamp(基础熟练命中 + 敏捷差修正 + 技能修正 + 位置修正 - 目标闪避 - 遮蔽修正, 5, 95)`
掷 d100 得 r，r ≤ H 为命中，否则未命中。5%–95%限制只用于普通攻击；明确必中或必定无法命中的特殊情形按技能说明处理。目标回避计入 H，不再对同一攻击额外掷闪避骰。

暴击独立于命中率成长，但可复用同一命中骰：设命中后的暴击概率 C，则暴击阈值为 floor(H×C)，r 不大于该阈值时暴击，其余命中为普通命中。例如 H=80、C=25%，r=1–20 暴击、21–80 普通命中、81–100 未命中。这样整体暴击率为20%，命中攻击中暴击率为25%。UI 同时明确“命中率”和“命中后暴击率”；阈值取整导致的实际值可在详细面板显示。技能特殊暴击规则由技能明确覆盖。

伤害原型：
`原始伤害 = 攻击力×技能系数 + 武器／技能伤害骰`
`有效防御 = max(0, 防御×(1-百分比破甲)-固定破甲)`
`最终伤害 = floor(原始伤害×位置倍率×暴击倍率×K/(K+有效防御))`
K 为用于调节防御收益的正数，初始提案100；普通非暴击倍率为1，初始暴击倍率提案1.5。“爆伤+20%”统一标成“暴击倍率+0.20”，避免相加还是相乘的歧义。常规非免疫命中最终伤害至少1，护盾与明确免疫另行结算。

示例：攻击20，技能系数1，伤害骰2d6掷出7，从背面攻击获得1.2倍；敌防御25，破甲为0，K=100。非暴击伤害 floor(27×1.2×100/125)=25；若暴击倍率1.5，则为38。这些只示范结算顺序，不作为正式平衡值。

站位技能原型：背刺要求进入目标背面弧区；突进沿合法直线路径接近并攻击；击退把目标推离；横扫攻击相邻扇区；远射要求视线通畅；盾击削减目标韧性。角色有四向朝向，攻击或技能后朝向目标；背面攻击区在界面清楚标出。位移遇障碍停止，不出现穿墙；碰撞额外伤害仅在技能明示时触发。射程、视线与走位本身通常确定性结算，不掷骰决定能否正常走到空格。

敌人显示攻击类型与范围预告，并区分“锁定地面区域”和“行动时重新瞄准目标”：前者可通过走位避开，后者不能只凭离开旧位置保证无伤。界面明确标识；精英通过限制地形、推进和区域攻击减少无限绕圈。

事件采用 d100 ≤ 有效技能值。感知用于侦察、发现陷阱与遗物线索，意志用于对抗恐惧、精神干涉与部分魔法控制；工具、装备和难度修正影响有效技能值。高难检定可使用半值／五分之一阈值作为设计选项，成功等级用于额外发现或更好事件结果，不自动等同于战斗暴击。材料和骰子规则都在确认前可查看。

普通武器的“鉴定物品”与事件中的“属性检定”区分：装备鉴定服务仍保证揭示信息；事件检定可以失败。不要把每次看装备词条也变成随机失败。

第一版操作反馈包括移动轨迹、路径成本、目标范围、概率预览、挥砍／射击动作、命中／闪避、暴击特效、击退和状态提示；每次攻击只展示主要结算，详细骰子日志可展开。普通结果演出允许加速。不以实时 QTE 为必要功能。

**5. 角色数值、词条与流派**

用户已确定使用经典 RPG 数值。将“当前不用考虑属性”暂按不做火／冰／雷等元素伤害、抗性和克制理解；保留角色基础数值、感知、意志与非元素魔法。若用户指的是另一种属性层，应再调整。

| 数值／机制 | 明确用途 | 边界 |
| --- | --- | --- |
| 攻击 | 武器与主要伤害技能的基础伤害 | 技能注明使用的系数，不同时叠多套隐含攻击公式 |
| 防御 | 减少直接伤害 | 采用平滑收益，避免轻易变成全免伤 |
| 生命 | 生存资源 | 与护盾区分 |
| 速度 | 每轮行动顺序 | 首版不直接增加行动次数 |
| 移动力 | 每回合可移动格数 | 通常为整数，词条较稀少 |
| 敏捷 | 部分命中／回避修正、机关与灵巧检定 | 不同时提高速度、移动力与暴击 |
| 暴击率 | 命中后造成暴击的概率 | 设上限，UI显示条件含义 |
| 暴击伤害 | 暴击倍率 | 统一相加单位并明示最终倍率 |
| 破甲 | 忽略目标部分防御 | 百分比和固定值顺序固定，不能降至负防御 |
| 韧性 | 对抗削韧与失衡 | 与防御减伤分开 |
| 流血 | 持续伤害状态 | 词条可提升施加能力、层数或持续伤害，分别命名 |
| 感知 | 侦察、陷阱、遗物与魔法线索识别 | 不直接提高所有掉率 |
| 意志 | 精神抵抗、魔法控制与相应事件检定 | 不强制引入完整元素系统 |

力量、体质、智力等传统能力值可后续补充；首版避免另起一层数值完全重复的六维加点体系。事件能力通过敏捷、感知、意志、战斗数值、技能标签和工具解决。非元素法术如冲击、护盾、束缚，采用技能写明的攻击或意志系数；感知负责识别魔法机关与目标特征。

韧性先采用清晰的韧性条：特定技能造成削韧，归零进入一次短暂失衡，并在恢复时重置韧性与提供短暂保护，避免永久控制。控制保护持续到目标下一回合结束，具体窗口需测试。韧性词条增加上限，不同时隐含提高闪避或减少所有伤害。

流血首版建议上限3层，目标回合结束结算，每层有明确剩余时间；重复施加按说明补层或刷新。流血默认不暴击，采用技能规定的伤害且不再乘一次攻击命中收益；是否绕过防御在技能中统一注明，原型暂定绕过防御。击杀、刷新和持续伤害的先后顺序保持可复现。

初始 8 个装备槽：主手、副手、头部、身体、手部、脚部、项链、戒指。双手武器占主副手。原型先开放4槽，MVP补齐。角色成长提供基础数值与技能选择，装备承担主要流派差异。

首批 3 个流派：重武器破甲／削韧；轻刃背刺／流血；非元素符文施法／控制与位移。是否保留魔法作为第三流派可在原型验证，现阶段不需要元素克制系统。

特殊技能词条示例：解锁“影步”短距离位移；背刺追加一层流血；突进命中后返还1点移动力（每回合一次）；盾击提高削韧；击杀后技能冷却减少一回合（每回合一次）；解锁短暂护盾或反击。随机重掷、修改骰面不作为首批词条核心。限制额外行动／冷却返还的触发次数，并禁止效果递归无限触发。

**6. 装备生成：稀有度、底材、词条与挖掘遗物**

装备数据分离为：基础模板、物品等级、稀有度、固有特性、随机词条、词条阶级与具体数值、打造状态、来源与鉴定状态。

| 维度 | 决定什么 | 设计约束 |
| --- | --- | --- |
| 底材 | 武器招式、基础值、尺寸、固定专长 | 不同底材有不同用途 |
| 物品等级 | 能出现的词条阶级 | 区域决定范围，避免全靠角色等级缩放 |
| 稀有度 | 随机词条数量和特殊能力资格 | 高稀有度不等于对当前角色必定更强 |
| 词条阶级 | 单条属性的强度档位 | 在界面明确显示 |
| 词条数值 | 同阶词条内部的浮动 | 显示范围与当前值，便于估值 |
| 遗物来源 | 特殊固有组合或定向掉落 | 不再叠加一个必须追逐的新颜色 |
| 打造状态 | 强化、附魔、保留词条 | 记录改造限制，出售时可见 |

建议稀有度：普通 0 条、魔法 1–2 条、稀有 3 条、史诗 4 条、传说 3 条加 1 个独特效果。这是原型规则，不是最终平衡。稀有与史诗可成为优质通用装备；传说负责改变玩法，不需要所有位置最终都换成橙色。

词条分三组：直接数值（攻击、防御、生命、速度、移动力、敏捷、暴击与爆伤等）、条件效果（背刺增伤、流血目标增伤、首次破甲获得护盾）、技能能力（解锁位移技能、提高削韧、改变攻击范围、有限次数的冷却返还）。同一互斥词条组不重复生成；词条按物品标签进入候选池，减少完全无用的组合，同时保留跨流派实验。

示例：“守誓者的裂纹长剑”，2×3 格，稀有，基础伤害 14，固有能力为攻击破甲目标获得少量护盾；词条为重击增伤 9%（区间 6–12%）、格挡效果 +2（区间 1–3）、背面攻击时提高伤害。它可能比一把四词条但偏向法术的史诗剑更适合当前角色。

吸收用户所说的“挖掘武器”体验：未鉴定遗物先揭示形状、武器家族、来源深度和模糊品质；回城揭示固有特性、词条与数值。特殊底材与独特固有组合由探索获得，商店不直接出售完整毕业装备。这里采用挖掘／鉴定式随机底材的设计意图，不依赖某一作品的具体数值规则。

控制多层随机：一件物品已有底材、稀有度、词条类型和数值，不再对所有装备额外叠加随机失败的鉴定、随机耐久上限和多层升星。遗物的特殊性是组合空间，鉴定本身不会失败。

避免无限垃圾：普通怪偏金币与材料，精英和宝箱承担主要装备产出；目标区域提高指定武器家族权重；首领掉落固定进度材料。可拆解低价值物品，重复探索仍推动定向制作。第一版不承诺固定掉落概率，先模拟并试玩调参。

**7. 格子背包、仓库与估值**

探索背包原型设为 6×5；回城仓库从 10×8 起，可分页扩建。道具可旋转 90 度，材料有堆叠上限，武器通常占多个格子。第一版只采用容量限制；重量、负重耐力和容器套容器暂缓，避免多个限制重复制造同一种压力。

整理背包在房间安全状态进行，不计现实时间惩罚。战斗中用快捷道具槽，不能通过无限整理或换装绕过行动成本。

| 信息 | 展示方式 | 玩家如何使用 |
| --- | --- | --- |
| 当前商人买入价 | 已鉴定后显示准确金币值 | 决定直接出售 |
| 每格价值 | 当前可卖价格／占格数 | 容量不足时快速比较 |
| 流派适配 | 标出与当前技能相关的词条和冲突 | 决定自用或为第二套配装收藏 |
| 打造潜力 | 显示底材、好词条、可修改项及成本 | 决定是否值得投入 |
| 委托用途 | 明确显示正在追踪的需求 | 防止卖掉目标物品 |
| 未鉴定估价 | 有依据的价格区间与未知字段 | 决定是否冒险占用空间 |

不要把“估值”做成一个神秘总评分。NPC 价格应可解释，但玩家仍需判断组合价值。高价可能来自稀有度，真正适合流派的便宜装备仍值得保留。

真实选择例：一把 2×3 大剑可卖 420，每格 70；一个 1×1 戒指可卖 160；一块 2×2 未鉴定遗物估价 150–700。戒指单位空间最划算，大剑可能是可直接使用的升级，遗物则带来高上限的不确定性。

仓库必备：拖拽、旋转、快速转移、按类型／词条搜索、筛选、锁定收藏、装备对比、套装保存、批量出售与拆解、可预览的自动整理。新获得物品有标记；已锁定物品不进入批量操作。失败拖拽返回原位置；出售与拆解确认清楚区分。商人界面关闭前可按原价赎回误卖物，确认离开后失效。

出城前进行空间提醒；回城结算提供不会静默丢物的暂存界面，玩家必须安置、出售或拆解后完成结算。仓库扩建先按经济解锁，不能让“购买格子”成为核心付费压力。

**8. 经济、打造与抽奖**

第一版以金币和 3 类制作材料为主，不同时引入大量货币。金币用于补给、基础装备、服务费、仓库升级；材料用于强化、定向改造和高阶制作。

| 系统 | 输入 | 输出 | 边界 |
| --- | --- | --- | --- |
| 基础商店 | 金币 | 可靠的入门装备、工具、药品 | 解决开荒和补缺，不稳定供应毕业底材 |
| 装备强化 | 金币＋材料 | 提升基础效果 | 低阶段保证成功，原型上限 +3，不碎装 |
| 附魔 | 金币＋对应材料 | 重铸一个词条 | 先显示可出词条；选定一个可改槽后其他槽固定；可保留旧结果 |
| 拆解 | 不需要的装备 | 制作材料 | 不返还全部历史投资，防止无成本循环 |
| 委托 | 指定战利品／探索成果 | 金币、配方、定向材料 | 有限额或刷新条件，避免无限买入交付套利 |
| 抽奖商人 | 金币 | 选定装备部位的随机普通至史诗装备 | 不含探索专属固有能力，公开池子与概率，只有游戏内金币 |
| 仓库扩建 | 金币＋阶段解锁 | 增加储存空间 | 早期便宜，避免掩盖刷宝乐趣 |

强化提供确定性，附魔修复“差一条就能用”的装备，抽奖是剩余金币的可选出口。三者不能都成为毕业前必须反复押注的随机关卡。第一版可以在核心循环验证之后才接入抽奖，但正式 MVP 包含简化版。

保值原则：好底材和特殊固有能力不能完全通过商店获得；附魔不能无限改成任意完美装备；强化让旧装备继续可用但不应取消探索新底材的理由。不要用失败碎装来强迫重新刷取。

平衡检查示例，数字仅是原型输入：假设一次探索成功撤离概率 70%；成功出售收入 900；每次补给成本 150；成功后维修 100，失败后维修 200；失败没有其他带回收入。则每局期望净金币为：

`0.7 × (900 - 150 - 100) + 0.3 × (0 - 150 - 200) = 350`

这些假设不包含自留装备价值、制作材料价值与一次性奖励。若小升级耗费 700 金币，大约两局期望收入可以承担，但真实体验还取决于失败波动与保留装备比例。平衡时分别核算金币、材料和装备留存，不把“所有物品都按卖价出售”当成玩家真实收入。

应模拟出售率、撤离率、打造消耗、抽奖回收价，以及购买→拆解→制作→出售的完整交易回路。抽奖平均卖回金币低于投入只解决直接倒卖，还需检查材料和委托兑换套利。仓库建设完成后仍应有合理的补给、打造与收藏消耗，但不要求通过高维护费耗尽所有收益。

**9. 失败惩罚与长期成长**

推荐默认规则：已装备物品和出发前携带的装备保留；本局拾取的未保护战利品及地城金币丢失；已消耗道具不恢复；装备受损并产生有上限的维修费；账号经验和图鉴记录保留。2×2 安全格可保护小件物品，不能放入超尺寸武器或把金币无限转成安全物品。

物品记录出发时身份与本局来源：途中换上新拾取装备并不能绕过战利品损失规则；出发时的原装备即使被替换进背包也仍受保护。拾取的大剑若想带回，仍需要成功撤离。

维修费不能形成负债死锁。提供免费基础武器、基础补给恢复或低风险救济委托，让玩家失败后总能重新出发。基础装备不会永久破碎。

后续可增加轻松模式（少丢战利品）与硬核模式（部分带入装备也会丢失）。第一版先做好一套默认体验，避免多个规则集分散测试。

长期目标来自探索深度、精英词缀、目标装备、稀有配方和图鉴。不要依赖每日签到、离线资源或不断清空仓库的赛季重置维持时长。

**10. 视听表现与美术生产：有特色的二次元**

用户已指定尽量有特色的二次元风格。推荐视觉提案为“遗迹拾荒×符文机械”：角色穿实用探险服、携带独特轮廓的背包与古代装备；地城把失落文明、机械构件与异常魔法结合。以墨蓝／灰白为环境底色，角色与遗物使用有限的青绿、朱红强调色。这是可修改的原创美术方向，尚未生成或确认风格样板。

采用日式动画感线稿与赛璐璐明暗；立绘保留角色个性，战斗用适度简化的二头身至三头身比例或纸偶骨骼角色。俯视／斜俯视战场要求清楚的朝向与前后关系，不能仅复用一张正面立绘代表所有方向。初期优先四向可读性，降低多方向动画成本。

特色由人物轮廓、服装层次、背包与武器设计、配色和符文图形形成。免费素材适合作为灰盒原型或经许可统一改造的辅助资源；成品核心角色、UI和背景应采用统一设计规范，不以不同免费包拼接作为最终风格。

AI用于角色设定、立绘、背景、事件插画和装备图标草案；角色拆层、动作关键帧、图标裁切和清晰度仍需整理。随机装备复用底材图标，通过品质边框和技能标记区别。动画至少包括待机、移动、攻击、受击、倒地、施法与位移；先为一名角色和一个敌人验证实际生产流程。

第一份风格样板应包含1个角色（立绘＋战斗比例与四向参考）、1个怪物、6个装备图标、1个房间和1套面板。确认可读性和风格后再批量扩展。优先让装备稀有度、路径、命中率、伤害区间和状态图标清晰可见。

AI仅用于制作阶段，运行时战斗、掉落与报价采用规则系统。音效重点放在脚步、武器命中、闪避、暴击、鉴定、落格与金币结算。长演出允许加速，屏幕震动可关闭。

Kenney官方说明其素材页游戏素材采用CC0，可用于商业项目；适合作为原型素材，不能因此假定其风格已经符合成品二次元方向。其他免费包逐一检查许可，建立素材来源与许可清单。[3]

**11. 引擎与发布建议**

Godot 为 MIT 开源引擎，官方允许商业使用；发行时应保留相关许可和第三方组件说明。[1] 本方案推荐 Godot 4 稳定版＋GDScript＋2D。具体版本在开工时锁定，不在策划阶段追逐最新版本。

| 选择 | 与本项目的匹配 | 主要取舍 |
| --- | --- | --- |
| Godot＋GDScript | 推荐；适合战斗场景、UI、动画、原生下载版与 Web 共用规则 | Web 性能、字体、存档和导出需从第一周验证 |
| Phaser＋TypeScript | 若纯网页优先，可考虑；官方为 MIT 的 2D Web 框架 [4] | 场景与工具链组织方式不同；下载版通常另配打包方案 |

这是基于项目需求的工程判断，不是引擎性能实测。没有必要同时实现两套引擎。

按核对时 Godot 稳定文档：Godot 4 的 Web 导出不能使用 C#；应使用 Compatibility 渲染路径，Web 需要 WebAssembly 和 WebGL 2.0。优先选择单线程导出，可降低跨源隔离配置负担。[2]

发布路径：第一阶段同时做最小 Windows 与 Web 导出验证；制作中网页用于快速试玩；完成垂直切片后交付网页链接和 Windows 包。正式优先平台由用户决定。Mac、Linux、移动端与手柄另行排期，不能因为引擎支持就默认已经适配。

单机版本无需自建游戏服务器。网页静态托管可评估免费额度，但不能承诺所有发行和长期流量均无成本；素材生成、音乐、商店上架和签名等成本另计，不预设当前价格。

网页存档不是天然跨设备同步。设计本地自动存档、手动导出／导入、备份槽和版本迁移；提示隐私模式、浏览器数据清理可能影响存档。[2] 账号云存档是后续独立功能。无竞争的单人游戏不以强反作弊为目标；若加入玩家交易、排行或在线经济，需改为服务端权威并重新估算范围。

**12. 系统实现边界**

数据定义与规则、界面、动画分开。规则产生动作结果，表现层播放结果，不能用动画完成顺序决定物品是否真正入库。

核心模块：探索状态、战斗结算、装备生成、背包仓库、经济交易、存档、UI／动画。装备与事件使用可校验的数据表；先保持一套权威数据，不同时维护多份手改表。每件装备使用唯一 ID，并记录底材、物品等级、词条、来源、强化、附魔状态、当前位置。

存档包括角色、仓库、金币、材料、地城进度、随机数状态、已结算事件、物品身份与版本号。战斗和掉落各用可复现的随机序列，便于复现错误；UI 特效不可消耗规则随机数。重要交易原子提交，保存前后不能重复领箱子、重复出售、金币扣除但装备消失。保留最近可用备份，导入数据校验数值与重复 ID。

值得做的自动验证：格子重叠与旋转边界、物品总量守恒、买卖／拆解扣款一致性、存读档往返、掉落约束与互斥词条、重复结算保护。战斗是否好玩仍需人工试玩；大量随机模拟只能发现极端数值与明显偏差。

**13. 第一版范围与制作顺序**

| 阶段 | 明确交付 | 通过条件 |
| --- | --- | --- |
| 规则原型 | 一个8×6战场、3个敌人、6个技能、移动／命中／伤害骰、临时掉落和格子包 | 10分钟里有真实走位与攻防取舍，命中／伤害结果可解释 |
| 垂直切片 | 一段地城、约 8 个经过节点、1 个首领、鉴定、商人、仓库、强化、存档、双端试跑 | 从出发到结算再到第二次出发完整可玩，能证明刷到装备会改变配装 |
| 正式 MVP | 一个主题地城、3 档深度、完整经济与 3 种流派 | 多次探索具有不同目标，失败后可恢复，经济不易被套利 |
| 内容扩展 | 新地城、特殊底材、更多独特能力、委托与终局挑战 | 建立在已验证循环上，不靠纯加数量修补无聊 |

正式 MVP 的内容预算上限提案：1 个角色，3 类武器，8 个装备槽，18 个装备底材，约 30 条随机词条、3 个传说独特效果；8 类普通敌人、2 种精英修饰和 1 个首领；12 个事件模板、6 类消耗品、1 名基础商人、1 个打造界面、1 个简化抽奖池。事件模板中的不同选项属于同一内容项，不能虚报为多份内容。

不包含：多人、交易所、动态玩家市场、完整 3D、开放世界、实时战斗与回合制两套并行、大规模剧情配音、运行时 AI 生成、完整手机触屏适配、赛季制、公会。若用户选择其中任一项，应相应缩减其他内容或扩大制作计划。

规划量级，仅用于判断投入：假设一名熟悉 Godot 的开发者、每周约 20 小时、素材主要复用，规则原型约 20–40 小时，垂直切片新增 60–120 小时，正式 MVP 新增 100–200 小时，集中平衡／表现／发布收尾新增 40–80 小时；合计约 220–440 小时，即 11–22 周。学习引擎、定制美术、大改战斗、平台问题和范围变化另计。AI辅助不消除人工试玩与返工成本。这不是交付承诺。v0.2新增战术格移动、寻路、视线、朝向及技能范围验证，并提高美术一致性要求；此前220–440小时是旧方案基线，暂不沿用为新版总估算。先用一个战场与一套角色动作测量工作量，再重估MVP。

**14. 评审与测试标准**

先用 5–10 名试玩者观察问题，不把小样本比例当作可靠市场预测。以下是内部假设门槛，原型结果可修改它们。

- 开场 3 分钟内完成一次可理解的战斗或探索决定，5 分钟内出现第一次有意义的战利品。
- 单局目标 15–25 分钟；普通战斗多为 3–5 回合，不靠漫长骰子演出拖时长。
- 玩家能解释“为什么留这件，为什么卖那件”，并能理解一次失败的主要原因。
- 同一套资源下，至少存在两种有情境差异的选择；不能所有回合都站在原地重复同一个技能；位移与站位加成应改变至少部分决策。
- 前期短时间内获得可用升级或明确制作进度；连续数局没有极品也不会毫无收获。
- 标准整理一次回城战利品约 1–3 分钟；超过时检查操作负担，而非仅增加仓库。
- 记录自留、出售、拆解比例，金币净流入／流出，撤离率，死亡位置，技能使用和重新开局意愿。
- 不接受物品丢失／复制、存档坏档、重开无限领取、负债无法出发、必需物品只能随机抽到等阻断问题。

若刷宝好玩但战斗重复，优先改敌人预告、地形与技能资源；若战斗好玩但仓库痛苦，优先改批量操作与掉落质量；若玩家从不冒险，检查损失是否过重；若永不撤离，检查容量、警戒与收益曲线。不要先扩大地图数量。

**15. 决策状态与 GitHub 开发准备**

已确认：行动后掷骰决定命中与伤害；事件检定参考COC／TRPG思路；加入移动力、站位加伤与位移技能；采用经典RPG数值、破甲、韧性、流血及特殊技能词条；保留感知、意志；美术为有特色的二次元。其余此前推荐方向按用户“其他看上去没有问题”作为原型默认，不重复请求确认。

原型默认：单机、Godot＋GDScript、节点探索＋小型格子战场、15–25分钟一局、保留带入装备而损失未保护的新战利品、网页试玩＋Windows下载。具体命中公式、暴击实现、格子大小与AP是设计建议，不代表用户已经逐条批准数值。

GitHub不是Godot开发的必需条件，项目可以先在本地使用Git记录版本。建议正式开发采用独立私有GitHub仓库，用于代码、策划、数据、素材许可记录和阶段版本管理；源码仓库与游戏部署目标分别决定。代码私有不要求游戏试玩也私有。

用户可以新建独立仓库，名称暂用 `dungeon-relics`。创建时选Private，勾选README即可；.gitignore与项目结构在初始化时补齐，暂不选整个项目的开源许可证，待用户决定项目是否开源。免费开源引擎与游戏自身是否开源是两个决定。GitHub官方支持创建时选择可见性和初始化文件。[5]

项目结构建议：`project.godot`、`scenes/`、`scripts/`、`data/`、`assets/`、`docs/`、`tests/`、素材许可清单及README。Godot生成缓存目录不提交；Godot能生成Git忽略与属性文件。[6] 大型原始美术文件是否采用Git LFS按实际大小和协作需要决定，在首次提交这些资源前设置。导出的游戏包作为发布产物，不反复提交到源码历史。

仓库创建后提供URL；私有仓库还需要开发环境对该仓库的授权访问。URL本身不是授权，当前尚未验证任何GitHub账户、仓库或写入权限。无需在聊天中提供密码或令牌。此轮没有创建仓库、写入GitHub或开始游戏实现。

下一步交付建议：先把已确认策划放入项目文档，开发一个战场、移动与朝向、命中／伤害判定、3个代表技能及最小掉落背包循环；在可玩的样例上评估节奏，再扩展内容。用户尚未指定的预算与投入时间保留为开放项，不阻碍继续细化原型。
